Implemented in the working tree. Follow-on steps are the v0.5 plan, not a second
implementation of this file.

**Audience:** a coding agent that must follow this file literally.
**Status:** plan only. Do not treat any formula below as a measured CS2 renderer.
**Snapshot this plan was written against:** 2026-09-23, repo version 0.3.0,
automatic model `quant-static-v5`, manual model `conditional-static-v4`,
target build **2000914**.
**Native old/new capture pairs in the repo:** zero. Leave that count at zero
unless a human adds reviewed captures. Never invent them.

Read this whole file before editing. Implement the phases in order. Stop at
the end of a phase if its tests fail. Do not skip ahead to “make the ML

## 0. What you must not do

These are hard stops. Violating one of them fails the task even if tests pass.

1. Do not edit anything under `research/archive/`. Do not change
   `research/archive/SHA256SUMS`.
2. Do not change `legacyGeometry` in `lib/legacy.js`. The old painter is the
   frozen binary32 reconstruction. New-renderer uncertainty is not a reason
   to “fix” the old side.
3. Do not wire `lib/quant/emulator.js` or `data/quant-emulator.json` into
   `infer`, the worker, or the Simple view. That artifact distills this
   repo’s own solver. Its labels are not game observations. Held-out
   full-tuple fidelity is about 35.7%. Using it as the converter would
   replace an exact search with a worse copy of the same guess.
4. Do not set any `speedGate`, `nativeEvidence`, or `nativeMatchProbability`
   field to an open or non-null success value. The modulator gate in this
   plan stays `closed-no-native-pairs`.
5. Do not guess a post-update share-code layout. Export cvar commands only.
6. Do not write hidden legacy cvars (`cl_crosshairsize`,
   `cl_crosshairthickness`, `cl_crosshairalpha`) into exported configs.
7. Do not add npm dependencies. Node 22.12+ and Python 3.10+ only.
8. Do not replace the shipped 27-model worker search with a 10,000-model
   cartesian product. A larger family belongs in an offline script until a
   human selects it.
9. Do not claim, in UI copy, comments that users see, or JSON reports, that
   a result is how Valve migrates settings. Allowed status strings are the
   ones already used (`conditional-not-game-validated`) plus the new ones
   named in this plan (`hypothesis-not-native`, `closed-no-native-pairs`).
10. Do not download game files from the browser. A maintainer may pin a dump

## 1. What the September 22, 2026 update actually changed

Official notes (Valve, September 22, 2026, “Rush Hour”):

- Crosshairs were updated to be resolution independent.
- Settings gained a Crosshair/Scopes tab and updated crosshair settings.
- New crosshair styles were added.
- The default crosshair became “Dynamic Quad.”

That paragraph does **not** publish the pixel formula. The cvar inventory
below is from SteamTracking `GameTracking-CS2` commit
`98da94fc084706334e85fcde5105d02224e30f0a`, build **2000914**, file
`DumpSource2/convars.txt`, re-read on 2026-09-23. It is game-derived tracker
data, not Valve renderer source. Descriptions support names, ranges, and
which fields claim to scale. They do not support a quantizer, a gap origin,
or a migration callback.

### 1.1 New geometry cvars

| Cvar | Default | Range | Description in the dump | Scales? |
| --- | --- | --- | --- | --- |
| `cl_crosshair_length` | 8 | 0–255 | Length of each crosshair bar, scaled with screen resolution | Description says yes |
| `cl_crosshair_thickness` | 2 | 0–31 | Thickness of the bars and circle, scaled with screen resolution (minimum 1 pixel) | Description says yes; stored 0 is legal |
| `cl_crosshair_gap` | 4 | 0–128 | Offset added to the gap between the crosshair center and the bars | Description does **not** say scaled |

### 1.4 The numerical trap in the dump defaults

Call `legacyGeometry({ size: 3.9, thickness: 0.6, gap: 0 }, 1080)`. It
returns length **8**, width **1**, gap offset **4**.

- New default length 8 matches that length.
- New default gap 4 matches that raw offset.
- New default thickness 2 does **not** match width 1.

So the dump defaults are not a migrated pair. Do not fit a conversion to
them. Add them as a regression fixture that asserts the disagreement.

### 1.5 What the current code already assumes, and where that is weaker than the dump

`lib/quant/renderer.js` `forward()` multiplies length, thickness, **and gap**
by the same ratio `r`. All 27 ids (`authored|reference1080|reference720` ×
`trunc|nearest|ceil` × `thickness|center|opening`) share that assumption.

The dump gives a reason to scale length and thickness, and no matching
sentence for gap. The old painter (`lib/legacy.js`, source S01) also did
**not** scale gap by height/480. It used raw pixels:

```text
length    = trunc(f32(H/480) * f32(size))
width     = max(1, trunc(f32(H/480) * f32(thickness)))
gapOffset = trunc(f32(f32(gap) + f32(4)))    # not multiplied by H/480
near      = floor(width/2) + gapOffset
far       = near + 1
```

A converter that scales the new gap by `H/A` can be right only if Valve
changed that rule. That is a hypothesis. It is currently an unstated axiom
of every shipped model. Phase 2 makes the axiom explicit and adds the
rival, without deleting the 27.

Other current limits to preserve until evidence arrives:

- Far displacement is fixed at 1 in the quant forward. The manual lab can
  vary it. Do not add new far-delta families in the hot path.
- `naiveAssignment` truncates old console numbers into the new ranges. It
  is the “copied values” preview. It is not migration. Size 2 at 1080p is
  4 pixels, so copied length 2 is the wrong pixel target.
- The learned emulator must stay research-only (chapter 10).

## 2. The conversion to implement

Separate four maps. A weaker agent will mix them up if they live in one
function. Keep them in different files.

```text
x, H_o  --F_old-->  z_o          lib/legacy.js          FROZEN
z_o, goal, H --T--> z_*          existing targetGeometry  unchanged contract
z_*, x, H, A --S_φ--> v          new structural inverse   hypothesis φ
v, H --R_φ--> ẑ                  new structural forward   same φ
v --Δ_θ--> v_hat                 residual modulator       weight 0 until native pairs
```

`φ` is a **discrete** hypothesis (which scale, which quantizer, which gap
origin). `θ` is a **small residual** that may only choose among equivalents
of `S_φ`. `θ` is not allowed to invent a different renderer.

### 2.1 Target geometry (do not redefine)

Same-pixel goal: `z_* = z_o`.
Screen-relative goal: `z_* = (H / H_o) * z_o` on length, width, near, and
far **after** the old quantizer. Do not re-run the old painter at `H`.
Gap did not scale in the old painter, so these two goals differ. Keep both.
The screen-relative goal is our matching choice, not Valve’s migration.

### 2.2 Structural forward

Create `lib/quant/structural.js`. Public exports:

```text
STRUCTURAL_VERSION = 'structural-forward-v1'
structuralForward(native, currentHeight, phi) -> { length, width, near, far, interval, scaleLength, scaleThickness, scaleGap, minimumBranch, phiId }
enumerateReducedFamily() -> phi[]          # the reduced set in §2.4, not the full product
phiId(phi) -> string                       # stable, sorted, no spaces
```

`phi` is a plain object. Validate it. Reject unknown enum values. Do not
accept arbitrary numbers for discrete fields.

```text
lengthRef, thicknessRef ∈ { authored, current, 1080, 720, 480 }
quantLength, quantThickness, quantGap ∈ { trunc, nearest, ceil }
gapScale ∈ { same-as-length, unscaled }
gapBase ∈ { thickness-half, center, opening-half }
zeroBranch ∈ { preserve-literal, positive-minimum }
farDelta = 1                                 # only this value in v1
biasLength = biasThickness = biasGap = 0     # only these values in v1
```

Reference height:

```text
authored -> native.authoredHeight
current  -> currentHeight          # r = 1; stored numbers are current pixels
1080     -> 1080
720      -> 720
480      -> 480
```

Ratio for a dimension is `currentHeight / referenceHeight`. Gap ratio is
that value only when `gapScale === 'same-as-length'` uses the **length**
ratio (not a separately chosen thickness ratio). When `gapScale ===
'unscaled'`, gap ratio is **1**. Do not multiply an unscaled gap by `H/A`
“just in case.”

Quantizer, nonnegative inputs only inside this function (the old negative
gap has already been mapped into a target edge, not into this quantizer):

```text
trunc(u)   = Math.trunc(u)          # toward zero; for u >= 0 this is floor
nearest(u) = Math.floor(u + 0.5)    # ties up; not banker's rounding
ceil(u)    = Math.ceil(u)
```

Forward:

```text
L = max(0, Q_L(r_L * lengthCvar + biasLength))

if thicknessCvar === 0 and zeroBranch === 'preserve-literal':
    W = 1
else:
    W = max(1, Q_T(r_T * thicknessCvar + biasThickness))

u = Q_G(r_G * gapCvar + biasGap)

thickness-half:  near = floor(W / 2) + u
center:          near = u
opening-half:    near = (u - 1) / 2
far = near + farDelta
```

`opening-half` has no dump sentence supporting it. Keep it as a sensitivity
alternative, off the default export path.

`bias*` exists in the object so a later native fit has a place to put the
old `+4` if measurements say the new zero point moved. **v1 must reject any
bias other than 0.** Do not “learn” a bias from the corpus. The corpus is
old inputs, not new observations.

### 2.3 Structural inverse

In the same file, export:

```text
invertStructural(settings, options, phi) -> {
  id, phi, native, predicted, target, legacy, residuals, status: 'hypothesis-not-native'
}
```

Use `targetGeometry` from `lib/quant/renderer.js` for `z_*` and
`legacyGeometry` for `z_o`. Do not reimplement the old painter.

Search integers in the documented ranges: length 0–255, thickness 0–31,
gap 0–128. Authored height is an input (`options.authoredHeight`), not a
searched dimension, in v1. Searching `A` as well makes the problem
non-identifiable (many `(cvar, A)` pairs share a ratio). Document that in
the return value’s `assumptions` array: `"authored height was supplied, not identified"`.

Order, matching the current joint inverse in `lib/quant/inverse.js`:

1. Length is separable. Minimize `(predictedLength - target.length) ** 2`.
   Tie-break: closer to `target.length / r_L`, then smaller integer.
2. Thickness and gap are joint, because a thickness-half baseline uses the
   predicted width. Exhaust thickness (32 values, or only 0 when
   `settings.thickness === 0` and `zeroBranch === 'preserve-literal'` and
   the target was not measured from an image). For each width, solve gap.
3. Gap loss is both edges, same as `gapBranch` today:

```text
center = (target.near + target.far - farDelta) / 2
loss(g) = (near(g) - target.near) ** 2 + (near(g) + farDelta - target.far) ** 2
```

4. Joint tie-break: lower thickness loss + gap loss, then closer to the
   continuous ideal, then smaller integers.
5. If old thickness is positive and the chosen thickness is 0, add the
   existing zero-branch warning. Do not “fix” it by clamping to 1. At
   `r = 2`, thickness 1 renders 2 pixels and hides a one-pixel miss.
   See correction C03.

Prefer the inverse-interval shortcut in §5.1 when the quantizer is `trunc`
or `nearest` and `gapBase !== 'opening-half'`. For `opening-half`, scan.

`exactWithinModel` is true only when length, width, near, and far residuals
are all `< 1e-9`, and only for arms (`legacy.length > 0`) does gap have to
match. It never means native validation. Put that sentence in a `scope`
string on the result, copied in meaning from `inverseCertificate.scope` in
`lib/quant/inverse.js`.

```text
lengthRef ∈ { authored, 1080, 720 }          # 3
quant     ∈ { trunc, nearest }               # 2   (ceil stays available but not in the reduced set)
```

Wait: 3 × 2 × 2 × 2 = 24. Use 24. Do not drop `unscaled` to save time.

```text
lengthRef: 'authored'
```

Add a report warning on every automatic result:

Do not change which native tuple `infer()` returns in the default path.

### 2.5 Named migration hypotheses (not the default)

Create `lib/migration.js`. These are candidates a user can inspect. They
are not `infer().chosen`.

**`pixelCopyCandidate(settings, oldHeight)`**

```text
z = legacyGeometry(settings, oldHeight)
length     = clamp(z.length, 0, 255)
thickness  = settings.thickness === 0 ? 0 : clamp(z.width, 1, 31)
gap        = clamp(z.gapOffset, 0, 128)
authoredHeight = oldHeight
```

If `z.gapOffset < 0` or `> 128`, set `gapClamped: true` and record the
unclamped value. Negative old offsets (example: gap `-5.1` at 1080 gives
gapOffset `-1`) **cannot** be stored in the new cvar. Say so. Do not shift
length to fake the overlap.

**`renameCandidate(settings, authoredHeight)`**

This is today’s `naiveAssignment`. Re-export it from `lib/migration.js` as
`renameCandidate` and keep `naiveAssignment` as a wrapper so old imports
work. Do not “improve” it.

**`structuralCandidate(settings, options, phi)`**

Thin wrapper around `invertStructural`.

Each returns `status: 'hypothesis-not-native'`.

### 2.7 What “modulation” means here

Modulation is not “predict the three cvars with a tree.”

Let `v_φ` be the integer tuple from `invertStructural` under a fixed `φ`.
A modulator may output an integer delta:

```text
Δ ∈ { -2, -1, 0, 1, 2 }³
v_hat = clip(v_φ + Δ, legal ranges)
```

v1 rule, which the code must enforce even if a future artifact contains
other weights:

```text
Δ = (0, 0, 0)
applied = false
reason = 'closed-no-native-pairs'
```

When a human later opens the gate, the allowed modulation is still narrow:

1. Discrete model selection picks `φ*` by group-disjoint native loss.
   That step is counting, not a neural net.
2. The residual model may only choose a tuple inside the **exact preimage**
   of the measured pixels under `R_φ*` (see `exactPreimage` in
   `lib/quant/inverse.js`), or a neighbor whose structural forward **does
   not increase** mask loss versus `v_φ*`.
3. If the unconstrained residual wants `|Δ| > 2` on more than 5% of
   training pairs, the structure is misspecified. Do not raise the clip.
   Write `speedGate: 'closed-structure-misspecified'` and stop.
4. Features may be functions of old settings, heights, and `v_φ` only.
   They must not include the native cvar label. They must not include a
   hash of the label. Fractional parts of `H_o/480 * size` **before**
   truncation are allowed; they mark quantization boundaries, which is
   where a wrong quantizer fails.
5. Split by legacy setting signature, `hash(signature) % 5 === 0` held out,
   same idea as chapter 10. Do not split by row.
6. Primary metric is exact full-tuple rate against **read-back native
   cvars**, on the held-out signatures. MAE is secondary. Do not report
   that rate as `nativeMatchProbability` in the app schema. Put it only in
   the research artifact.
7. Direct tuple regression (what `emulator.js` does) stays forbidden on
   the conversion path. It may remain in the research script it already has.

Minimum evidence before anyone may even **run** a non-zero fit (the script
must exit 0 and write a zero artifact if this fails; it must not throw a
stack the UI could treat as data):

- at least 40 reviewed native pairs
- at least 24 distinct old-setting signatures
- at least 3 distinct current heights, including one pair with `H ≠ A`
  and one pair with `H = A`
- both odd and even rendered widths
- at least one literal thickness 0 and one positive thickness
- at least one negative old gap and one nonnegative old gap
- build id equal to the model’s declared build
- provenance not equal to `synthetic-example` or `user-entered`

`research/measurements/index.json` is the empty registry. Do not populate
it. The trainer reads it, sees fewer than 40 reviewed pairs, and writes a
closed artifact. That is the successful v1 outcome.

## 3. Performance

Do these only after Phase 2 tests pass. Do not trade correctness for speed.

1. **Inverse intervals instead of blind scans**, in `structural.js` only
   at first. For `trunc` and `r > 0`, the integers `v` with
   `trunc(r v) = k` are those in `[k/r, (k+1)/r)`. Intersect with
   `0..max`. If the intersection is empty, scan the full range once and
   keep the minimum residual (saturation at the ends). For `nearest`, the
   interval is `[(k-0.5)/r, (k+0.5)/r)`. Do not use the interval shortcut
   for `opening-half` or for a non-zero bias.
2. **Validate once per request**, then call an internal unchecked predict
   from the search. The exported `structuralForward` keeps validation so
   UI callers stay safe. Do not export the unchecked function.
3. **Do not rank 24 structural hypotheses inside `infer()`** on the default
   path. Add `scripts/structural-study.mjs` and `npm run study:structural`
   that scores the 24 offline on the existing corpus and writes
   `research/generated/structural-disagreement.json`. That file records how
   often `same-as-length` and `unscaled` disagree. It is not a vote for
   either family.
4. **Cooperative cancel between models, not inside pixel loops.** In the
   worker, check the request generation after each of the 27 models. A
   check per candidate integer will cost more than it saves.
5. **Keep the corpus in the worker.** Do not transfer it per keystroke.
   Do not add cross-request memoization keyed only on settings: evidence
   sets change the likelihood. Memo keys that omit evidence are a
   correctness bug.
6. **Leave the emulator unwired.** A 3× speedup that is wrong on 64% of
   tuples is not a performance win for this app.

Acceptance: `npm run bench:quant` still finishes. Median time may move.
Do not commit a new timing file as a golden CI value. The existing policy
in `docs/engineering/quant-architecture.md` says timings are local.

## 4. Security

The app is a static local converter. The risk is imported text and images,
not accounts. Keep that boundary.

1. **Legacy CFG parser** (`lib/cfg.js`): if the line matches
   `cl_crosshair_length`, `cl_crosshair_thickness`, `cl_crosshair_gap`, or
   `cl_crosshair_screen_height`, throw a dedicated error:
   `New-build cvars cannot be imported as legacy settings. Paste the old cl_crosshairsize / thickness / gap block, or edit the proposed values.`
   Still reject every other unknown command. Still reject `exec`, `bind`,
   `connect`, aliases, and quoted non-numeric values. Add tests for each.
2. **Export denylist test:** `exportCFG` / `nativeCommands` output must not
   contain these as command tokens: `cl_crosshairsize`,
   `cl_crosshairthickness`, `cl_crosshairalpha`, `cl_crosshairgap` (the
   no-underscore name), `cl_crosshairusealpha`, `cl_crosshaircolor` followed
   by a space and a digit, `exec`, `bind`, `connect`, `host_writeconfig`.
   Match tokens. `cl_crosshair_gap` must still be present. A naive
   `includes('cl_crosshairgap')` check is wrong because `cl_crosshair_gap`
   does not contain that substring — use a regex with a boundary after
   `gap` so `_gap` is not confused, and a separate check that the
   underscore form **is** emitted.
3. **Do not add a new share-code decoder.** If a code fails legacy v1
   checks, the existing error stays. You may append one sentence: new-format
   codes are not parsed. Do not try base64, bit flips, or “version 2.”
4. **Worker messages:** cap the JSON payload at 1 MiB before decode logic
   runs, matching the evidence UI cap in `docs/engineering/quant-architecture.md`.
   Reject non-object messages. Keep the 30-second deadline. On worker
   failure, keep the current behavior: disable conversion, do not fall
   back to an unbounded main-thread search.
5. **Measurement JSON** still cannot mark itself verified. The new trainer
   must ignore every provenance except a reviewed-registry value that this
   plan does **not** define. Since that value does not exist, the trainer
   always takes the closed branch. Do not add `native-verified` as an
   accepted importer provenance.
6. **No new network calls** from `app/` or `lib/`. `scripts/check.mjs`
   already rejects `eval`, `new Function`, and `innerHTML` assignment in
   `app/`. Extend that check to `lib/` if it is not already covered. Do not
   weaken the CSP in `docs/engineering/deployment.md`.
7. **Comments in cfg** already go through `safeComment`. Keep that. Also
   reject exported numeric fields that are not safe integers in range,
   which `validateNative` already does. Call it. Do not interpolate
   `settings` strings into commands.

## 5. Code quality

1. Put range constants in `lib/native-settings.js` and import them
   everywhere a literal `255`, `31`, or `128` currently means a cvar range:

```text
export const NATIVE_RANGES = Object.freeze({
  length: Object.freeze({ min: 0, max: 255 }),
```
