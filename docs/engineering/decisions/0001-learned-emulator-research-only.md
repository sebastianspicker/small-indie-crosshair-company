# 0001 — The learned emulator is research-only

**Source:** [`docs/math/10-learned-emulator.md`](../../math/10-learned-emulator.md),
[archived v0.4 plan §0.3](../archive/v0.4-conversion-improvement-plan.md).

## Context

`research/lib/emulator.js` is a dependency-free learned inverse/forward model,
trained offline (`npm run emulator:train`) on labels generated by the
project's own declared solver (`infer()`), not on CS2 captures. Its held-out
full-tuple fidelity to that solver is about 35.7% (up from an earlier 11.6%
after a capacity revision); its companions, `research/lib/ranker.js` (a learned
shortlist verified exactly against the declared loss) and
`research/lib/sensitivity.js` (analytic and learned fragility advisories), and
`research/lib/modulator.js` (a residual correction on top of the exact solver)
are all scoped the same way: they measure fidelity to the project's own
equations, never accuracy against the game. The project ships zero native
old/new capture pairs, so nothing in the repository can validate a learned
model against the real renderer.

## Decision

The learned emulator, ranker, sensitivity layer and modulator never enter the
shipped conversion path. The exact finite-domain solver (`lib/solver/inverse.js`
via `lib/solver/inference.js`) is the only inverse the app runs. These modules
are research artifacts: reproducible, measured and documented, but not wired
into `app/` at any point.

## Consequences

- `research/lib/emulator.js`, `ranker.js`, `sensitivity.js` and `modulator.js`
  must stay unreachable from `app/main.js` and `app/worker/worker.js`.
  `tests/tooling/boundaries.test.mjs` enforces this by walking the shipped import
  graph and asserting these modules are absent from it; a module entering the
  shipped path fails that test and shows up as an explicit reachability diff.
- Training and benchmarking scripts (`research/scripts/train-quant-emulator.mjs`,
  `research/scripts/benchmark-emulator.mjs`, `research/scripts/benchmark-ranker.mjs`,
  `research/scripts/train-residual-modulator.mjs`) write versioned artifacts under
  `research/generated/`; none of those artifacts is read by `app/`.
- Documentation (chapter 10, the quant lab section of
  [architecture](../architecture.md)) must keep describing these modules as
  research-only rather than as part of the conversion path, so a reader
  cannot mistake solver-fidelity numbers for native accuracy.
